# Supabase backend

- `migrations/` — versioned SQL schema changes.
- `functions/` — Edge Functions for operations that need server-side secrets,
  such as calling the LLM provider (Milestone 5).
- `config.toml` — CLI project config, generated by `supabase init`.

## One-time setup (per machine)

Run these two commands yourself in a terminal — they need an interactive
browser login and your database password, neither of which should be typed
into a chat with Claude:

```bash
npx supabase login
npx supabase link --project-ref otrtxtkghhnxmmfqgvdr
```

After that, migrations can be applied with:

```bash
npx supabase db push
```

## AI generation secret (Milestone 5)

The `generate-quiz` function needs an OpenAI API key as a Supabase secret —
run this yourself (never paste a real key into a chat with Claude):

```bash
npx supabase secrets set OPENAI_API_KEY=sk-...
```

Deploy the function itself with:

```bash
npx supabase functions deploy generate-quiz
```

## Account deletion secret

The `delete-account` function needs the service-role key (already available
to every Edge Function as `SUPABASE_SERVICE_ROLE_KEY` — no separate secret to
set). Deploy it with:

```bash
npx supabase functions deploy delete-account
```

## Feedback email alert (Suggestions screen)

Emails the product owner when a teacher submits a suggestion. Three secrets,
none of them committed to the repo:

```bash
# From resend.com (free tier, no card required): Settings > API Keys.
npx supabase secrets set RESEND_API_KEY=re_...

# Where the alert is sent.
npx supabase secrets set FEEDBACK_ALERT_EMAIL=you@example.com

# A random string only you and the webhook know — generate one with:
#   openssl rand -hex 32
npx supabase secrets set FEEDBACK_WEBHOOK_SECRET=<random string>
```

Deploy the function:

```bash
npx supabase functions deploy notify-feedback
```

The trigger that calls this function on every `feedback` insert lives in
`20260914120000_notify_feedback_trigger.sql` (via `pg_net`, not the Studio
"Database Webhooks" UI — that feature errored with `schema
"supabase_functions" does not exist` on this project, a platform-side
provisioning gap, so the trigger is defined directly in SQL instead, fully
covered by `db push`). It still needs the same `FEEDBACK_WEBHOOK_SECRET` value, stored in Supabase
Vault rather than a migration literal — run this yourself in the Supabase
SQL editor (never commit a real secret to a migration). `alter database ...
set` doesn't work on hosted Supabase (`permission denied to set parameter`
— the platform doesn't allow instance-level custom parameters), Vault is
the supported alternative for a secret a function needs to read:

```sql
select vault.create_secret('<same random string as FEEDBACK_WEBHOOK_SECRET>', 'feedback_webhook_secret');
```

If that errors with something like `schema "vault" does not exist`, enable
the `supabase_vault` extension first (Database → Extensions), then retry.

Then:

```bash
npx supabase db push
```

Without a verified sending domain in Resend, `onboarding@resend.dev` (the
default `from` address) can only deliver to the email address your Resend
account itself is registered with — fine as long as `FEEDBACK_ALERT_EMAIL`
is that same address. Verifying your own domain in Resend later removes that
restriction.
